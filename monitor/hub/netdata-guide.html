Netdata 白話導覽

Netdata 是給維運人員看的工具，一打開有幾十張圖，很容易迷路。這頁只教你「該看哪裡」和「什麼情況才要擔心」。平常看總覽頁就夠了，只有想查細節時才進 Netdata。

第 0 步：先過兩個畫面

  1. 先輸入帳號密碼（瀏覽器跳出的小視窗，帳號 chijiun）。這是我們自己設的門鎖。
  2. 進去後會看到 Welcome to Netdata, Please sign-in。不用註冊、不用登入 Netdata，點最下方的小字 Skip and use the dashboard anonymously 就好。
  3. 如果一開始看到的是一頁「Database / System / Modules / Directories」的資訊表，那只是安裝資訊，不是圖表。跳過登入後才是真正的圖表頁。

畫面上只有這幾個地方要認識

位置是什麼
Metrics（上方分頁）所有圖表都在這。你主要看這個分頁。
Alerts（上方分頁）警告清單。旁邊的數字：紅色是嚴重（critical）、橘色是警告（warning）。兩個都是 0 代表沒事。
右上角時間範圍預設只看「最近 15 分鐘」。想看更久，點它改成 1 小時、1 天等。
右側 Charts圖表目錄。點一下可以跳到 System、CPU、Memory、Disks、Networking、Containers 等區塊。
其他分頁Nodes、Live、Logs、Events、Anomalies、AI Insights、Dashboard，這個單機環境用不到，可以忽略。

介面文字是英文，這是 Netdata 本身的設計，無法改成中文。

在 Metrics 頁依序看這幾個地方

  1. 最上面的 6 個圓形儀表（System）：磁碟讀、磁碟寫、CPU、記憶體（RAM）、網路接收、網路送出。這是「現在這一刻」的快照，一眼就知道整台機器忙不忙。
  2. 往下捲到 CPU 區的「Total CPU utilization」：折線圖，橫軸是時間，縱軸是百分比。看有沒有長時間貼著 100%。短暫的尖峰是正常的。
  3. Memory 區：看「已用」有沒有一直往上爬、不下來，那通常代表某個程式有問題。
  4. 想知道是哪個程式在吃資源：在右側 Charts 目錄找 Containers 相關的區塊（圖表名稱含 cgroup），每個 Docker 容器（stats-ai、ncu-backend、uptime-kuma…）各有一組 CPU、記憶體圖。
  5. 想知道網站有多少人來：找名稱含 caddy 的圖，是每個網域的請求數。

這 5 項大多已經整理在總覽頁的趨勢圖裡，而且是白話標題。Netdata 的好處是可以放大到「每秒」，查「為什麼剛剛卡了一下」。

什麼情況才要擔心

看到什麼代表要不要處理
CPU 長時間（超過 10 分鐘）接近 90～100%機器被某個程式用滿要查是哪個容器
記憶體用量超過 90%，而且還在上升可能有程式漏記憶體，快用完會被系統強制關掉程式要查
磁碟用量超過 90%硬碟快滿了要清理
Alerts 出現紅色數字嚴重問題點進去看是什麼
Alerts 出現橘色數字警告，通常不急點進去看，多半可以排程處理
數字都很低（CPU 2%、記憶體 18%）機器很閒不是壞事。只有「Oracle 會不會回收」那一項要另外留意，見總覽頁第 4 節
目前實際的例子：Alerts 有一個橘色警告「System requires reboot after package updates」，意思是「系統更新過核心，要重新開機才會生效」。這不是故障，只是提醒你找個時間重開機。
常見疑問
圖是一格一格的，我看不出重點？
先只看最上面 6 個圓形儀表和 Alerts 就好，其餘的是查問題時才用。
我可以弄壞什麼嗎？
不會。Netdata 這個頁面只能看，不能改機器的任何設定。
為什麼只有「最近 15 分鐘」？
那是預設值。右上角的時間範圍可以改，Netdata 在這台保留約 7 天的每秒資料、更久的資料會變粗略。
跳出「Sign in」一直問我？
每次清除瀏覽器資料後都可能再問一次，一樣點 Skip 即可，不需要 Netdata 帳號。

打開 Netdata →在新畫面裡記得先點 Skip and use the dashboard anonymously。
