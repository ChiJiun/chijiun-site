我搶到一台免費的雲端主機：Oracle Always Free ARM VM 的實際過程

2026-11-13 · 約 20 分鐘讀完
  • Oracle Cloud
  • 雲端主機
  • ARM
  • Always Free
  • 雲端價格

Oracle Cloud 提供一台長期免費的 ARM 雲端主機（2 核、12 GB 記憶體），但要拿到它沒那麼簡單：我花了約 42 分鐘、試了 24 次才成功。這篇用我自己的實際過程，說明這是什麼、為什麼要「搶」、怎麼做，以及我踩到的坑。

這篇在講什麼

如果你想要一台可以 24 小時開著的 Linux 主機，拿來跑自己的小專案、機器人或實驗，又不想每個月付錢，Oracle Cloud 的 Always Free 是其中一個選擇。我這次實際把它申請下來，並且把過程整理成可以照著做的紀錄。

  • 你會看到：什麼是雲端主機、Always Free 包含什麼、我怎麼用一支腳本重複申請、搶到之後做了哪些檢查。
  • 你需要：一個 Oracle Cloud 帳號、會用一點命令列、一台能長時間開機的電腦。
  • 你不會看到：我的帳號識別碼、IP、信箱或金鑰，文中都用 <佔位符> 取代。

先講清楚：能不能搶到有運氣成分，沒有人能保證多久。文中的免費額度數字來自 Oracle 官方文件，我只讀了其中一頁，計費細節沒有逐項查證。

什麼是「免費的雲端主機」

雲端主機（VM）就是租用別人機房裡的一台虛擬電腦：你用網路登入它，它不會因為你關電腦而停機，也有自己的公開 IP。平常租用要按時間和規格計費。

Oracle 的 Always Free 是在帳號內提供一小份固定額度，在額度內不收費。我這次要的是其中的 A1 ARM 主機：ARM 是手機和 Apple 晶片也在用的處理器架構，這份額度是 2 核（OCPU）、12 GB 記憶體，對個人用途來說相當寬裕。

為什麼要「搶」

「搶」的意思是：向 Oracle 要求建立這台主機時，請求可能失敗，所以要不斷重試，直到某一次成功。一般的說法是免費額度的主機數量有限、同一區域容易沒有空位，但這是我聽來的說法，我沒有留下錯誤訊息可以驗證。

  • 我的腳本前 23 次都被判定為「可以稍後重試的錯誤」，第 24 次才成功。
  • 我當時沒有把 CLI 回傳的原始錯誤訊息存下來，所以沒辦法逐次確認原因，只知道這些都不是設定錯誤。
  • 手動在網頁上一直按「建立」也行，只是我選擇用腳本，因為腳本可以固定間隔、不間斷地重試。

搶到之後可以拿來做什麼

這一節是我的想法，我還沒有在這台主機上實際跑過任何服務，所以只能算建議，不是經驗。

  • 跑小型的網站、API 或聊天機器人，讓它一直在線。
  • 跑排程腳本，例如定時抓資料或通知。
  • 當作自己的測試機，練習 Linux、Docker 或部署流程。

要注意的限制：這台是 ARM 架構，只有 x86 版或只能在 Windows 上跑的程式不能直接用；也沒有 GPU，不適合跑大型模型。

整個流程一眼看完

  1. 準備工具：建立 API 金鑰、安裝 OCI CLI（Oracle 的命令列工具）、設定連線。
  2. 建網路：主機要放在一個虛擬網路裡，建 VCN、Internet Gateway、路由與公開子網路。
  3. 查三個值：映像檔（作業系統）、可用區、子網路的識別碼。
  4. 跑腳本：重複申請，直到成功。
  5. 確認主機可用：查狀態、查 IP、用 SSH 登入。
  6. （選配）：另外開一台 AMD 小主機。
給 agent 的執行摘要（點開）

前置條件：已有 Oracle Cloud 帳號、home region、OCI API 金鑰與 ~/.oci/config；本機有 bash、oci 指令、SSH 公鑰。

  1. 驗證：oci iam region-subscription list --tenancy-id <TENANCY_OCID>，預期 home region 狀態為 READY。（唯讀）
  2. 查配額：oci limits value list --service-name compute；免費額度以官方文件為準，規格固定 2 OCPU / 12 GB。（唯讀）
  3. 建網路：VCN、Internet Gateway、預設路由表加 0.0.0.0/0、公開子網路。（會在帳號建立資源，先問使用者）
  4. 查映像檔 OCID 與 AD 名稱。（唯讀）
  5. 送出 oci compute instance launch，失敗時依錯誤類型決定等待重試或停止（見步驟 4）。（會建立主機，先問使用者）
  6. 完成條件：oci compute instance list 出現狀態 RUNNING 的同名主機，且能用 ssh ubuntu@<IP> 登入。

限制：作者只在 Windows 加 Git Bash 環境實際跑過；沒有在其他系統重跑；所有識別碼都要換成使用者自己的值，不要把金鑰印出來。

  • 升級 Pay As You Go 之後，Always Free 資源仍然免費，只有超出額度的部分才計費。
  • 7 天內 CPU 的第 95 百分位低於 20%，而且網路、記憶體（記憶體只看 A1）的使用率也低於 20%，主機可能被當成閒置回收。官方文字只明確寫 CPU 是第 95 百分位，網路與記憶體怎麼取樣，文件沒有細說。
  • Reserved Public IP 是否免費，文件沒有載明，所以我沒建。
  • 免費規格可選的映像檔只有 Linux，沒有 Windows。

我的帳號用 CLI 查到的 A1 配額上限遠大於免費額度（region 16 核 / 96 GB）。那是配額上限，不是免費額度，超過 2 OCPU / 12 GB 的部分可能計費，所以腳本預設就卡在 2 / 12。

如果不用免費的，其他雲端大概要多少錢

搶這台主機的時候，我很好奇：一樣規格的主機，在別的雲端一個月要付多少？以下是我在 2026-11-13 查到的公開牌價，不是我實際使用過的帳單。

先看限制。沒有任何一家剛好是「2 核 ARM、12 GB 記憶體」，下表是最接近的規格，不能當成同規格比價。價格都是牌價（list price），不含稅、折扣、承諾使用折扣與試用抵用額度，月費一律用 730 小時換算，之後可能調整，要用之前請自己再查一次。多數官方價目頁是動態網頁，我有一部分是從官方的價目資料檔或 API 讀取，不一定和網頁上看到的完全一致。

怎麼算的

  • Oracle：A1 隨用隨付是每 OCPU 每小時 $0.01、每 GB 記憶體每小時 $0.0015、區塊儲存每 GB 每月 $0.0255。2 × 730 × $0.01 + 12 × 730 × $0.0015 + 50 × $0.0255 ≈ $29.02。價目資料裡 A1 另有一段免費區間，但它的數字（約 4 OCPU / 24 GB）和官方免費額度頁寫的 2 OCPU / 12 GB 對不上，原因我不確定，所以我不拿它當依據，免費額度一律以官方頁面為準。這份價格沒有標示區域，「全球同價」我沒有驗證。
  • AWS：東京、Linux、隨用隨付的每小時價乘以 730，再加 EBS gp3 每 GB 每月 $0.096 × 50 GB。另外公有 IPv4 位址每小時 $0.005（約每月 $3.65），上表沒有計入。其他服務商的公有 IP、快照、備份等附加費用，我也都沒有計入。
  • Google Cloud：T2A 在官方區域選單裡沒有東京，所以用新加坡；T2A 不支援自訂機型，沒辦法湊成 12 GB。磁碟以 Balanced 持久碟每月 $0.11/GB 估算。
  • Azure：日本東部、Linux 的每小時價乘以 730，再加 64 GiB 的 Standard SSD（50 GB 會被往上取整到這一級）每月約 $4.80。換成 Premium SSD 約 $11.74，每月會多約 $7。
  • Hetzner：這兩款是歐洲機房，沒有亞洲地點，我查到的頁面也顯示它們暫時無法購買，所以只能當價位參考。

出站流量（我覺得最容易被忽略）

Oracle 官方免費額度頁寫每月 10 TB 出站流量免費，這個數字在這張表裡是最大的差別。其他三家的牌價（我只列單價，不算總額，因為分級與目的地不同）：

  • AWS：每月前 100 GB 免費，超過後東京出站約每 GB $0.114（前 10 TB）。
  • Azure：每月前 100 GB 免費，超過後約每 GB $0.11～$0.12，取決於路由方式；哪一種是預設，我沒有驗證。
  • Google Cloud：新加坡或東京出站到亞洲約每 GB $0.11～$0.12；官方頁上我沒看到免費額度，標為「查不到」。

所以如果你的主機會有大量對外流量，費用差距會比機器本身大得多。

我查不到或不確定的部分

  • Scaleway 等其他業者：官方價目頁讀不到，我沒有寫進來。
  • Hetzner 超額流量的單價，頁面文字看起來有誤，我沒有引用。
  • 表裡 Hetzner 是歐元（且不含 VAT），其他是美元，我沒有換算，所以 Hetzner 那兩列不能和其他列直接比較。
  • 這些是公開牌價，不構成任何購買建議。

步驟 1：準備 OCI CLI 與 API 金鑰

1.1 建立 API 金鑰

  1. 登入 Console，右上角頭像 → My profile → API keys → Add API key。
  2. 選 Generate API key pair，下載私鑰，再按 Add。
  3. 畫面會顯示一段設定檔內容，裡面有 user、fingerprint、tenancy、region，先留著。
  4. 把私鑰放到 ~/.oci/oci_api_key.pem，並限縮權限（只有自己可讀寫）。

1.2 建立設定檔

把剛才的內容存成 ~/.oci/config，並把 key_file 改成私鑰的實際路徑：

[DEFAULT]
user=<USER_OCID>
fingerprint=<API_KEY_FINGERPRINT>
tenancy=<TENANCY_OCID>
region=ap-tokyo-1
key_file=<私鑰的完整路徑>

Always Free 只能開在 home region，所以 region 要填你註冊時選的那個。

1.3 安裝 OCI CLI（Windows 要注意路徑長度）

建議裝在獨立的 Python 虛擬環境裡，而且路徑要很短，原因在後面「踩坑」一節。我最後用的是：

py -3 -m venv C:\o
C:\o\Scripts\python.exe -m pip install oci-cli
C:\o\Scripts\oci.exe --version

驗證金鑰是否正確（唯讀指令）：

oci iam region-subscription list --tenancy-id <TENANCY_OCID> --output table

看到你的 home region 狀態是 READY，代表金鑰和 fingerprint 都正確。

1.4 查 A1 配額

oci limits value list --compartment-id <TENANCY_OCID> --service-name compute --all --query "data[?contains(name,'standard-a1')]"

我的帳號查到的上限遠大於免費額度（region 16 核 / 96 GB），但那是配額上限，不是免費額度，所以後面的腳本把規格固定在 2 OCPU / 12 GB。

步驟 2：建網路

主機需要 VCN、Internet Gateway、路由和公開子網路。下面是 PowerShell 版本，全部建在 root compartment。官方的免費額度頁只列了 VCN 的數量上限，沒有明說這些網路資源收不收費，建議建完之後到 Billing 自己確認。

$T = "<TENANCY_OCID>"

$vcn = oci network vcn create --compartment-id $T --cidr-block 10.0.0.0/16 `
  --display-name a1-vcn --wait-for-state AVAILABLE --query "data.id" --raw-output

$igw = oci network internet-gateway create --compartment-id $T --vcn-id $vcn `
  --is-enabled true --display-name a1-igw --wait-for-state AVAILABLE `
  --query "data.id" --raw-output

# 預設路由表加一條 0.0.0.0/0 指向 Internet Gateway
$rt = oci network vcn get --vcn-id $vcn --query "data.\`"default-route-table-id\`"" --raw-output
'[{"destination":"0.0.0.0/0","destinationType":"CIDR_BLOCK","networkEntityId":"' + $igw + '"}]' |
  Set-Content -Encoding ascii routes.json
oci network route-table update --rt-id $rt --route-rules "file://C:/路徑/routes.json" --force

# 公開子網路
$sub = oci network subnet create --compartment-id $T --vcn-id $vcn --cidr-block 10.0.0.0/24 `
  --display-name a1-public --wait-for-state AVAILABLE --query "data.id" --raw-output

預設的安全清單（Security List）本來就放行 TCP 22，我用下面的指令確認，沒有改它：

$sl = oci network vcn get --vcn-id $vcn --query "data.\`"default-security-list-id\`"" --raw-output
oci network security-list get --security-list-id $sl --query "data.\`"ingress-security-rules\`""

預設是對 0.0.0.0/0 開放 SSH。搶到之後建議把來源限縮成自己的 IP，並考慮停用密碼登入。

步驟 3：查建立主機需要的三個值

# Ubuntu 24.04 ARM 映像檔
oci compute image list --compartment-id $T --operating-system "Canonical Ubuntu" `
  --operating-system-version "24.04" --shape VM.Standard.A1.Flex `
  --sort-by TIMECREATED --sort-order DESC --limit 1 --query "data[0].id" --raw-output

# Availability Domain 名稱
oci iam availability-domain list --compartment-id $T --query "data[].name"

子網路 OCID 就是上一節建出來的那個。另外要準備一把 SSH 金鑰：公鑰在建立主機時交給 Oracle，之後登入就用對應的私鑰。我用的是自己電腦上原本就有的一把。

步驟 4：重複申請，直到成功

核心動作只有一個：對 Oracle 送出「建立主機」的請求。成功就結束，失敗就等一下再送。我用一支 bash 腳本（在 Windows 上用 Git Bash 執行）重複這件事，這裡不貼完整腳本，只列出建立主機用的指令（bash 語法，和前面步驟的 PowerShell 不同；識別碼換成你自己的值）：

oci compute instance launch \
  --compartment-id <TENANCY_OCID> \
  --availability-domain <AD_NAME> \
  --display-name a1-free \
  --shape VM.Standard.A1.Flex \
  --shape-config '{"ocpus":2,"memoryInGBs":12}' \
  --image-id <IMAGE_OCID> \
  --subnet-id <SUBNET_OCID> \
  --boot-volume-size-in-gbs 50 \
  --assign-public-ip true \
  --ssh-authorized-keys-file <SSH 公鑰檔> \
  --wait-for-state RUNNING

我的腳本把這個指令放在迴圈裡，每次失敗後等 60 秒再送；送出前會先用 --display-name 的名字查有沒有已經存在的主機，有就停止；每次嘗試的時間與結果會寫進 log。

我實際跑的版本，成功後會用 python 從回應裡解析主機 ID，結果解析失敗，所以腳本寫在 log 與結果檔（腳本另外存主機 ID 與 IP 的檔案）裡的主機 ID 與公開 IP 都是空的。主機其實已經建好了，我是另外用 CLI 查到 IP。

成功與否，最後都要用 oci compute instance list 實際確認。

步驟 5：讓它在背景跑，並確認狀態

這支腳本需要一直開著，電腦不能睡眠。我是在 Windows 上用 Git Bash 執行，並讓它在背景運作，另外用指令查它的 log。

log 長這樣，沒搶到時會一直重複這兩種訊息（log 只記錄腳本的判定，我沒有把 CLI 的原始錯誤訊息存下來，所以我無法逐次確認每次的原因）：

[時間] 第 N 次嘗試，AD=<AD_NAME>，2 OCPU / 12 GB
[時間] 可重試錯誤，60 秒後再試

成功的那一次，log 會寫下「成功」；我這次因為前面說的解析問題，那一行後面的主機 ID 與 IP 是空的，所以最後仍要用 oci compute instance list 確認。

步驟 6：搶到之後，確認主機可用

  1. 用 CLI 確認狀態是 RUNNING、規格是 2 / 12，並查出公開 IP。
  2. 用 SSH 登入。Ubuntu 的預設使用者是 ubuntu，Oracle Linux 是 opc： 
    ssh ubuntu@<PUBLIC_IP>
  3. 登入後檢查系統： 
    uname -m        # aarch64
free -h         # 約 11 GiB 可用
df -h /         # 約 48 GB

我沒有建 Reserved IP（固定 IP）。我拿到的是系統自動配的臨時 IP，它重開機後會不會變，我沒有測；官方免費額度頁沒有寫到 Reserved IP，所以我沒有建；如果你需要固定 IP，請先查 Oracle 的定價頁。

加碼：順便開一台 AMD 小主機

AMD 小主機是獨立額度，我只試了一次就開成功（一次的結果，不代表一定容易）。但它是 x86、只有 1 GB 記憶體，跟 ARM 的差異如下：

A1 ARMAMD 小主機
CPU 架構ARM（aarch64）x86_64
CPU2 核1/8 OCPU，可短暫借用額外 CPU
記憶體12 GB1 GB（可用約 700 MB）
頻寬較高最高 50 Mbps（官方文件）
 
oci compute instance launch --compartment-id $T --availability-domain "<AD_NAME>" `
  --shape VM.Standard.E2.1.Micro --image-id "<X86_UBUNTU_IMAGE_OCID>" `
  --subnet-id "<SUBNET_OCID>" --display-name e2-free-1 --boot-volume-size-in-gbs 50 `
  --assign-public-ip true --ssh-authorized-keys-file <SSH 公鑰檔> --wait-for-state RUNNING

x86 映像檔要用 --shape VM.Standard.E2.1.Micro 去查，ARM 映像檔不能用在它上面。兩台加起來我用了 100 GB 磁碟，離 200 GB 上限還有空間。

我實際開的資源，與官方文件寫的限制

  • 我實際開的：一台 A1（2 OCPU / 12 GB、50 GB 磁碟）加一台 AMD 小主機（50 GB 磁碟），磁碟合計 100 GB，沒有超過官方文件寫的 200 GB。
  • 官方文件寫的閒置回收規則：Always Free 主機若 7 天內 CPU 的第 95 百分位低於 20%，而且網路、記憶體（記憶體只看 A1）使用率也低於 20%，可能被回收。我才剛搶到，還沒有觀察到實際會不會被回收，所以這部分我沒有經驗可以分享。
  • 我沒有做的：Reserved IP（文件沒說免不免費）、負載平衡器、其他額外資源。

我踩到的坑

坑 1：Windows 路徑長度上限（最大的一個）

pip install oci-cli 失敗了兩次，錯誤是找不到檔案，並提示系統沒有啟用長路徑。原因是 oci-cli 內建了幾千個說明檔，有些檔名超長，放在 C:\Users\<你>\... 這種深路徑底下，完整路徑會超過 Windows 預設的 260 字元。

  • 虛擬環境放在 Temp 底下、或 C:\Users\<你>\ov，還是失敗。
  • 縮到 C:\o 才成功。
  • 另一個做法是啟用 Windows 長路徑，但那是系統設定，我選擇不動它。用 WSL 或 Linux 機器也能繞過這個問題。

坑 2：虛擬環境建不起來

在很深的資料夾裡 python -m venv 會卡在 ensurepip，同樣是路徑長度造成的，換到短路徑就好。

坑 3：PowerShell 的 JMESPath 跳脫

--query 裡的欄位名稱有連字號（例如 default-route-table-id）就必須加引號。PowerShell 要寫成 "data.\`"default-route-table-id\`""，bash 則是 'data."default-route-table-id"'。沒跳脫會看到 Unknown token '-'。

這個反斜線加反引號的寫法，我只在 Windows PowerShell 5.1 上實測過。PowerShell 7.3 之後改了傳給外部程式的引數處理方式，這寫法可能失效，到時請改用單引號版本；7.x 我沒有環境，沒測。

坑 4：--route-rules file:// 的路徑

Windows 路徑要用正斜線：file://C:/路徑/routes.json，用反斜線會被當成多餘的參數。

坑 5：腳本的結果檔 IP 是空的

前面「步驟 4」提過：我實際跑的版本用 python 解析主機 ID，解析失敗，log 與結果檔裡的主機 ID 與公開 IP 都是空的。主機已經建好，我另外用 oci compute instance list 和 list-vnics 查到 IP。

我學到的

  • 這次我的 A1 是在第 24 次嘗試搶到，前面 23 次都被腳本判定為可重試錯誤，沒有出現會讓腳本停止的錯誤。我沒有存下原始錯誤訊息，所以不能保證每一次的原因都是沒容量。
  • 在 Windows 上裝 oci-cli，路徑要夠短，我最後是裝在 C:\o 才成功。
  • 升級 Pay As You Go 和搶到的時間很接近，但我沒查升級有沒有生效，無法判斷兩者有沒有關係。
  • 免費額度以 Oracle 官方文件為準，我只讀了其中一頁，計費細節沒有逐項查證。
