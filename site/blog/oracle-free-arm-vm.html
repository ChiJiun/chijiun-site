Oracle Cloud 提供一台長期免費的 ARM 雲端主機（2 核、12 GB 記憶體），但要拿到它沒那麼簡單：我花了約 42 分鐘、試了 24 次才成功。這篇整理它的免費額度、要不要升級 Pay As You Go（PAYG）、其他雲端同規格大概多少錢，再用我自己的實際過程，從申請一路寫到把個人網站放上去。

什麼是「免費的雲端主機」

雲端主機（VM）就是租用別人機房裡的一台虛擬電腦：你用網路登入它，它不會因為你關電腦而停機，也有自己的公開 IP。平常租用要按時間和規格計費。

Oracle 的 Always Free 是在帳號內提供一小份固定額度，在額度內不收費。我這次要的是其中的 A1 ARM 主機：ARM 是手機和 Apple 晶片也在用的處理器架構，這份額度是 2 核（OCPU）、12 GB 記憶體，對個人用途來說相當寬裕。

免費額度與 Pay As You Go（PAYG）

Always Free 包含什麼

資源額度
A1 ARM 主機合計 2 OCPU / 12 GB，可以用在一台，或最多切成兩台
AMD 小主機VM.Standard.E2.1.Micro 最多 2 台，每台 1 GB 記憶體
磁碟開機磁碟與區塊磁碟合計 200 GB
出站流量每月 10 TB
位置主機與磁碟只能建在 home region（註冊時選的 region）
  • 7 天內 CPU 的第 95 百分位低於 20%，而且網路、記憶體（記憶體只看 A1）的使用率也低於 20%，主機可能被當成閒置回收。
  • Reserved Public IP 是否免費，文件沒有載明，所以我沒建。
  • 免費規格可選的映像檔只有 Linux，沒有 Windows。

我的帳號用 CLI 查到的 A1 配額上限是 16 核 / 96 GB，那是配額上限，不是免費額度，超過 2 OCPU / 12 GB 的部分可能計費，所以規格固定在 2 / 12。

Free Trial、Always Free、PAYG 的關係

名稱官方文件怎麼寫
Free Trial$300 的雲端抵用額度，最多 30 天，可以花在任何符合資格的服務。
Always Free不會到期的固定免費額度。試用結束後帳號仍然有效，已經建好的 Always Free 資源不會中斷。
Pay As You Go（PAYG）付費帳號，沒有承諾期，超出免費額度的部分才計費。升級後，Always Free 資源仍然免費。
  • 註冊多半需要手機號碼與信用卡；官方寫信用卡在升級之前不會被扣款。
  • 試用結束時，如果 A1 主機的總量超過 Always Free 的 2 OCPU / 12 GB，官方寫這些 A1 主機會先被停用，30 天後刪除，除非升級。所以建議一開始就把規格固定在 2 / 12。

一定要升級 PAYG 才能拿到免費主機嗎？

我讀到的官方 Free Tier 文件，沒有寫「要升級才能建立 Always Free 主機」，也沒有寫升級會讓申請成功的機率變高。

  • 網路上有人說要先升級。我自己也升級了，但時間點非常接近我搶到的時候，而且我沒有確認升級是什麼時候生效，所以我不能說升級有幫助，也不能說沒有。
  • 要不要升級是你的決定。升級之後要自己留意別開到超出免費額度的資源，超出的部分會計費。

怎麼升級

官方寫法：在 Console 頂端橫幅點 Upgrade 連結；如果沒看到，點左上角的 Oracle Cloud 標誌，到首頁右側欄找 Upgrade。官方說升級後仍然能使用所有現有的雲端資源。我是在 Console 按升級並填付款資訊。

為什麼要「搶」

向 Oracle 要求建立這台主機時，請求可能失敗，所以要不斷重試，直到某一次成功，這就是「搶」。一般的說法是免費額度的主機有限、同一區域容易沒有空位，但我沒有留下錯誤訊息可以驗證。我的腳本前 23 次都被判定為「可稍後重試的錯誤」，第 24 次才成功。手動在網頁上反覆按「建立」也行，我選擇用腳本，因為它可以固定間隔、不間斷地重試。

整個流程一眼看完

  1. 準備工具：建立 API 金鑰、安裝 OCI CLI（Oracle 的命令列工具）、設定連線。
  2. 建網路：主機要放在一個虛擬網路裡，建 VCN、Internet Gateway、路由與公開子網路。
  3. 查三個值：映像檔（作業系統）、可用區、子網路的識別碼。
  4. 跑腳本：重複申請，直到成功。
  5. 確認主機可用：查狀態、查 IP、用 SSH 登入。
  6. （選配）：另外開一台 AMD 小主機。
  7. 部署網站：開放 80/443、安裝 Caddy、放上網站檔案、設定自動更新。
  8. 切換網域：把網域的 DNS 改指向這台主機。

前置條件：已有 Oracle Cloud 帳號、home region、OCI API 金鑰與 ~/.oci/config；本機有 bash、oci 指令、SSH 公鑰。

  1. 驗證：oci iam region-subscription list --tenancy-id <TENANCY_OCID>，預期 home region 狀態為 READY。（唯讀）
  2. 查配額：oci limits value list --service-name compute；免費額度以官方文件為準，規格固定 2 OCPU / 12 GB。（唯讀）
  3. 建網路：VCN、Internet Gateway、預設路由表加 0.0.0.0/0、公開子網路。（會在帳號建立資源，先問使用者）
  4. 查映像檔 OCID 與 AD 名稱。（唯讀）
  5. 送出 oci compute instance launch，失敗時依錯誤類型決定等待重試或停止（見步驟 4）。（會建立主機，先問使用者）
  6. 完成條件：oci compute instance list 出現狀態 RUNNING 的同名主機，且能用 ssh ubuntu@<IP> 登入。
  7. 部署網站（步驟 7）：在 Security List 與 VM 的 iptables 開 TCP 80/443、安裝 Caddy、複製網站、設定每 2 分鐘 git pull 的 systemd timer，並用 curl http://<IP>/ 驗證。（會改雲端防火牆與主機設定，先問使用者）
  8. 切換網域：在 DNS 服務商把網域指向主機 IP。（會讓現有網站短暫切換，先問使用者；不要動不相關的記錄）

限制：作者只在 Windows 加 Git Bash 環境實際跑過；沒有在其他系統重跑；所有識別碼都要換成使用者自己的值，不要把金鑰印出來。

一般雲端主機要多少錢（同規格牌價比較）

搶這台主機的時候，我很好奇：一樣規格的主機，在別的雲端一個月要付多少？以下是我在 2026-11-13 查到的公開牌價，不是我實際使用過的帳單。

雲端主機的費用通常由哪幾塊組成

以下是一般的計費方式說明，每家細節不同，請以各家價目頁為準：

  • 運算：CPU 核數與記憶體，通常按小時計費，月費大約是每小時價乘以 730。
  • 磁碟：開機磁碟與額外磁碟，按容量（GB）每月計費，不同等級的磁碟單價差很多。
  • 出站流量：從雲端流出去的流量，各家通常給一小段免費量，超過後按 GB 計費；流進來的流量一般不收費。
  • 公有 IP：有些業者另外收費（例如 AWS 的公有 IPv4）。
  • 其他：快照、備份、負載平衡器、監控等，用到才算。

同規格牌價比較

先看限制。沒有任何一家剛好是「2 核 ARM、12 GB 記憶體」，下表是最接近的規格，不能當成同規格比價。價格都是牌價（list price），不含稅、折扣、承諾使用折扣與試用抵用額度，月費一律用 730 小時換算，之後可能調整，要用之前請自己再查一次。多數官方價目頁是動態網頁，我有一部分是從官方的價目資料檔或 API 讀取，不一定和網頁上看到的完全一致。

怎麼算的

  • Oracle：A1 隨用隨付（見 Oracle 價目表）是每 OCPU 每小時 $0.01、每 GB 記憶體每小時 $0.0015、區塊儲存每 GB 每月 $0.0255。2 × 730 × $0.01 + 12 × 730 × $0.0015 + 50 × $0.0255 ≈ $29.02。
  • AWS：東京、Linux、隨用隨付的每小時價乘以 730，再加 EBS gp3 每 GB 每月 $0.096 × 50 GB。另外公有 IPv4 位址每小時 $0.005（約每月 $3.65），上表沒有計入。其他服務商的公有 IP、快照、備份等附加費用，我也都沒有計入。
  • Google Cloud：T2A 在官方區域選單裡沒有東京，所以用新加坡；T2A 不支援自訂機型，沒辦法湊成 12 GB。磁碟以 Balanced 持久碟每月 $0.11/GB 估算。
  • Azure：日本東部、Linux 的每小時價乘以 730，再加 64 GiB 的 Standard SSD（50 GB 會被往上取整到這一級）每月約 $4.80。換成 Premium SSD 約 $11.74，每月會多約 $7。
  • Hetzner：這兩款是歐洲機房，沒有亞洲地點，我查到的頁面也顯示它們暫時無法購買，所以只能當價位參考。這一列是歐元、不含 VAT，不能和其他列直接比較。這些都是公開牌價，不構成購買建議。

出站流量（我覺得最容易被忽略）

Oracle 官方免費額度頁寫每月 10 TB 出站流量免費，這個數字在這張表裡是最大的差別。其他三家的牌價（我只列單價，不算總額，因為分級與目的地不同）：

  • AWS：每月前 100 GB 免費，超過後東京出站約每 GB $0.114（前 10 TB）。
  • Azure：每月前 100 GB 免費，超過後約每 GB $0.11～$0.12，取決於路由方式；哪一種是預設，我沒有驗證。
  • Google Cloud：新加坡或東京出站到亞洲約每 GB $0.11～$0.12；官方頁上我沒看到免費額度，標為「查不到」。

所以如果你的主機會有大量對外流量，費用差距會比機器本身大得多。

步驟 1：準備 OCI CLI 與 API 金鑰

1.1 建立 API 金鑰

  1. 登入 Console，右上角頭像 → My profile → API keys → Add API key。
  2. 選 Generate API key pair，下載私鑰，再按 Add。
  3. 畫面會顯示一段設定檔內容，裡面有 user、fingerprint、tenancy、region，先留著。
  4. 把私鑰放到 ~/.oci/oci_api_key.pem，並限縮權限（只有自己可讀寫）。

1.2 建立設定檔

把剛才的內容存成 ~/.oci/config，並把 key_file 改成私鑰的實際路徑：

[DEFAULT]
user=<USER_OCID>
fingerprint=<API_KEY_FINGERPRINT>
tenancy=<TENANCY_OCID>
region=ap-tokyo-1
key_file=<私鑰的完整路徑>

Always Free 只能開在 home region，所以 region 要填你註冊時選的那個。

1.3 安裝 OCI CLI（Windows 要注意路徑長度）

建議裝在獨立的 Python 虛擬環境裡，而且路徑要很短，原因在後面「踩坑」一節。我最後用的是：

py -3 -m venv C:\o
C:\o\Scripts\python.exe -m pip install oci-cli
C:\o\Scripts\oci.exe --version

驗證金鑰是否正確（唯讀指令）：

oci iam region-subscription list --tenancy-id <TENANCY_OCID> --output table

看到你的 home region 狀態是 READY，代表金鑰和 fingerprint 都正確。

1.4 查 A1 配額

oci limits value list --compartment-id <TENANCY_OCID> --service-name compute --all --query "data[?contains(name,'standard-a1')]"

查到的是配額上限，不是免費額度；規格一律固定在 2 OCPU / 12 GB（見前面的警告）。

步驟 2：建網路

主機需要 VCN、Internet Gateway、路由和公開子網路。下面是 PowerShell 版本，全部建在 root compartment。官方的免費額度頁只列了 VCN 的數量上限，沒有明說這些網路資源收不收費，建議建完之後到 Billing 自己確認。

$T = "<TENANCY_OCID>"

$vcn = oci network vcn create --compartment-id $T --cidr-block 10.0.0.0/16 `
  --display-name a1-vcn --wait-for-state AVAILABLE --query "data.id" --raw-output

$igw = oci network internet-gateway create --compartment-id $T --vcn-id $vcn `
  --is-enabled true --display-name a1-igw --wait-for-state AVAILABLE `
  --query "data.id" --raw-output

# 預設路由表加一條 0.0.0.0/0 指向 Internet Gateway
$rt = oci network vcn get --vcn-id $vcn --query "data.\`"default-route-table-id\`"" --raw-output
'[{"destination":"0.0.0.0/0","destinationType":"CIDR_BLOCK","networkEntityId":"' + $igw + '"}]' |
  Set-Content -Encoding ascii routes.json
oci network route-table update --rt-id $rt --route-rules "file://C:/路徑/routes.json" --force

# 公開子網路
$sub = oci network subnet create --compartment-id $T --vcn-id $vcn --cidr-block 10.0.0.0/24 `
  --display-name a1-public --wait-for-state AVAILABLE --query "data.id" --raw-output

預設的安全清單（Security List）本來就放行 TCP 22，我用下面的指令確認，沒有改它：

$sl = oci network vcn get --vcn-id $vcn --query "data.\`"default-security-list-id\`"" --raw-output
oci network security-list get --security-list-id $sl --query "data.\`"ingress-security-rules\`""

預設是對 0.0.0.0/0 開放 SSH。搶到之後建議把來源限縮成自己的 IP，並考慮停用密碼登入。

步驟 3：查建立主機需要的三個值

# Ubuntu 24.04 ARM 映像檔
oci compute image list --compartment-id $T --operating-system "Canonical Ubuntu" `
  --operating-system-version "24.04" --shape VM.Standard.A1.Flex `
  --sort-by TIMECREATED --sort-order DESC --limit 1 --query "data[0].id" --raw-output

# Availability Domain 名稱
oci iam availability-domain list --compartment-id $T --query "data[].name"

子網路 OCID 就是上一節建出來的那個。另外要準備一把 SSH 金鑰：公鑰在建立主機時交給 Oracle，之後登入就用對應的私鑰。我用的是自己電腦上原本就有的一把。

步驟 4：重複申請，直到成功

核心動作只有一個：對 Oracle 送出「建立主機」的請求。成功就結束，失敗就等一下再送。我用一支 bash 腳本（在 Windows 上用 Git Bash 執行）重複這件事，這裡不貼完整腳本，只列出建立主機用的指令（bash 語法，和前面步驟的 PowerShell 不同；識別碼換成你自己的值）：

oci compute instance launch \
  --compartment-id <TENANCY_OCID> \
  --availability-domain <AD_NAME> \
  --display-name a1-free \
  --shape VM.Standard.A1.Flex \
  --shape-config '{"ocpus":2,"memoryInGBs":12}' \
  --image-id <IMAGE_OCID> \
  --subnet-id <SUBNET_OCID> \
  --boot-volume-size-in-gbs 50 \
  --assign-public-ip true \
  --ssh-authorized-keys-file <SSH 公鑰檔> \
  --wait-for-state RUNNING

我的腳本把這個指令放在迴圈裡，每次失敗後等 60 秒再送；送出前會先用 --display-name 的名字查有沒有已經存在的主機，有就停止；每次嘗試的時間與結果會寫進 log。

成功與否，最後都要用 oci compute instance list 實際確認。

步驟 5：讓它在背景跑，並確認狀態

腳本需要一直開著，電腦不能睡眠。我在 Windows 上用 Git Bash 執行並放在背景，另外查它的 log。沒搶到時，log 會一直重複這兩種訊息：

[時間] 第 N 次嘗試，AD=<AD_NAME>，2 OCPU / 12 GB
[時間] 可重試錯誤，60 秒後再試

成功時 log 會寫「成功」。我這次那一行後面的主機 ID 與 IP 是空的（見坑 4），所以最後仍要用 oci compute instance list 確認。

步驟 6：搶到之後，確認主機可用

  1. 用 CLI 確認狀態是 RUNNING、規格是 2 / 12，並查出公開 IP。
  2. 用 SSH 登入。Ubuntu 的預設使用者是 ubuntu，Oracle Linux 是 opc： 
    ssh ubuntu@<PUBLIC_IP>
  3. 登入後檢查系統： 
    uname -m        # aarch64
free -h         # 約 11 GiB 可用
df -h /         # 約 48 GB

加碼：順便開一台 AMD 小主機

AMD 小主機是獨立額度，我只試了一次就開成功（一次的結果，不代表一定容易）。但它是 x86、只有 1 GB 記憶體，跟 ARM 的差異如下：

A1 ARMAMD 小主機
CPU 架構ARM（aarch64）x86_64
CPU2 核1/8 OCPU，可短暫借用額外 CPU
記憶體12 GB1 GB（可用約 700 MB）
頻寬較高最高 50 Mbps（官方文件）
 
oci compute instance launch --compartment-id $T --availability-domain "<AD_NAME>" `
  --shape VM.Standard.E2.1.Micro --image-id "<X86_UBUNTU_IMAGE_OCID>" `
  --subnet-id "<SUBNET_OCID>" --display-name e2-free-1 --boot-volume-size-in-gbs 50 `
  --assign-public-ip true --ssh-authorized-keys-file <SSH 公鑰檔> --wait-for-state RUNNING

x86 映像檔要用 --shape VM.Standard.E2.1.Micro 去查，ARM 映像檔不能用在它上面。兩台加起來我用了 100 GB 磁碟，離 200 GB 上限還有空間。

步驟 7：把個人網站放上這台主機

搶到主機後，我做的第一件事，是把這個個人網站搬上來。網站是純靜態檔案（沒有後端、不需要 build），所以只需要一個網頁伺服器。我選 Caddy：設定檔很短，之後要自動申請 HTTPS 憑證也容易。以下是我實際做的順序，<VM_IP> 代表主機的公開 IP。

7.1 開放 80 與 443（兩層防火牆）

要讓外界連到網站，有兩層都要放行：Oracle 的 Security List（雲端那一層），以及 Ubuntu 映像檔自己的 iptables。我兩層都只加 TCP 80 與 443。

Security List 的 update 是整份取代，所以要先取出現有的入站規則、加上新的、再整份送回去：

$sl = "<SECURITY_LIST_OCID>"
# 先備份現有的入站規則
oci network security-list get --security-list-id $sl --query "data.\`"ingress-security-rules\`"" > ingress-backup.json
# 把現有規則加上 80 與 443 之後，存成 ingress-new.json（UTF-8，不要有 BOM）
oci network security-list update --security-list-id $sl `
  --ingress-security-rules "file://C:/路徑/ingress-new.json" --force

新增的每一條規則長這樣（443 同理）：

{"protocol":"6","source":"0.0.0.0/0","source-type":"CIDR_BLOCK","is-stateless":false,
 "tcp-options":{"destination-port-range":{"min":80,"max":80}}}

主機這一層，這個 Ubuntu 映像檔預設的 INPUT 規則最後一條是拒絕，所以新規則要插在它前面。我先用 sudo iptables -S INPUT 看過順序，再插入並存檔，重開機後才不會消失：

sudo iptables -I INPUT 5 -p tcp -m state --state NEW --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -p tcp -m state --state NEW --dport 443 -j ACCEPT
sudo netfilter-persistent save

7.2 安裝 Caddy

照 Caddy 官方的安裝說明，用官方的 apt 套件庫（Debian／Ubuntu）：

sudo apt-get install -y debian-keyring debian-archive-keyring apt-transport-https curl gpg git
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/gpg.key | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt-get update && sudo apt-get install -y caddy

7.3 放上網站檔案，並設定自動更新

網站放在 GitHub 上，我直接在主機上 git clone，Caddy 指向裡面放網頁的資料夾：

sudo mkdir -p /var/www/chijiun && sudo chown ubuntu:ubuntu /var/www/chijiun
git clone https://github.com/<帳號>/<repo>.git /var/www/chijiun

/etc/caddy/Caddyfile（先只聽 80，用 IP 測試）：

:80 {
	root * /var/www/chijiun/site
	encode zstd gzip
	file_server
	handle_errors {
		rewrite * /404.html
		file_server
	}
}

為了讓網站在我 push 之後自己更新，我用 systemd timer，每 2 分鐘執行一次 git pull --ff-only（chijiun-sync.service 與 chijiun-sync.timer 放在 /etc/systemd/system/）：

# chijiun-sync.service
[Service]
Type=oneshot
User=ubuntu
WorkingDirectory=/var/www/chijiun
ExecStart=/usr/bin/git pull --ff-only --quiet

# chijiun-sync.timer
[Timer]
OnBootSec=1min
OnUnitActiveSec=2min
[Install]
WantedBy=timers.target
sudo systemctl daemon-reload
sudo systemctl enable --now chijiun-sync.timer
sudo systemctl reload caddy

7.4 先用 IP 測試

在切換網域之前，先從外面用 IP 確認網站正常：

curl -I http://<VM_IP>/                 # 200，Server: Caddy
curl -I http://<VM_IP>/不存在的路徑       # 404，內容是自訂的 404 頁

7.5 把網域改指向主機（以 Cloudflare 為例）

我的網域放在 Cloudflare，原本由 Cloudflare Workers 提供網站，www 則指向 GitHub Pages。切換的順序是：

  1. 先在 VM 準備好 HTTPS。Cloudflare 的 SSL/TLS 模式原本就是「完整（Full）」，這個模式接受來源伺服器上不受信任的憑證，所以我先用 Caddy 內建 CA 的憑證，Caddyfile 加一個網域區塊： 
    chijiun.com, www.chijiun.com {
	tls internal
	import site
}
    （site 是把上面原本 :80 區塊裡的設定抽成的 (site) 片段。）
  2. 在 Workers 的專案裡，移除自訂網域。這會一起刪掉網域根目錄那條 Worker 記錄，網站從這一刻到下一步完成之間是中斷的。
  3. 在 DNS 新增一筆 A 記錄：名稱 @，內容是主機的 IP，開啟橘雲（Proxy）。
  4. 把 www 那筆 CNAME 的目標，從舊的 GitHub Pages 網址改成網域本身。

完成後，網域根目錄和 www 都回 200。要確認流量真的打到這台主機，可以在主機上用 ss 看有沒有 Cloudflare 的 IP 連到 443。

7.6 我還沒做的

  • 把 tls internal 換成 Let's Encrypt 的正式憑證，並把 Cloudflare 的 SSL/TLS 改成 Full (strict)。目前 Cloudflare 到主機之間的加密有效，但憑證不會被驗證。
  • 固定 IP（Reserved IP）。主機現在用的是系統自動配的臨時 IP，我沒有測過它重開機後會不會變，所以目前不要停用或刪除這台主機。

我踩到的坑

坑 1：Windows 路徑長度上限

pip install oci-cli 失敗了兩次，錯誤是找不到檔案並提示沒有啟用長路徑；在很深的資料夾裡 python -m venv 也會卡在 ensurepip。原因是 oci-cli 內建大量說明檔、檔名很長，放在 C:\Users\<你>\... 這種深路徑底下，完整路徑會超過 Windows 預設的 260 字元。虛擬環境放在 Temp 或 C:\Users\<你>\ov 都失敗，縮到 C:\o 才成功。也可以啟用 Windows 長路徑（系統設定，我沒動）或改用 WSL／Linux。

坑 2：PowerShell 的 JMESPath 跳脫

--query 裡的欄位名稱有連字號（例如 default-route-table-id）就必須加引號。PowerShell 要寫成 "data.\`"default-route-table-id\`""，bash 則是 'data."default-route-table-id"'。沒跳脫會看到 Unknown token '-'。

這個寫法我只在 Windows PowerShell 5.1 實測過，PowerShell 7.x 沒測。

坑 3：--route-rules file:// 的路徑

Windows 路徑要用正斜線：file://C:/路徑/routes.json，用反斜線會被當成多餘的參數。

坑 4：腳本的結果檔 IP 是空的

我實際跑的版本在成功後用 python 從回應解析主機 ID，解析失敗，所以 log 與結果檔裡的主機 ID 與公開 IP 都是空的。主機已經建好，我另外用 oci compute instance list 和 list-vnics 查到 IP。

坑 5：Security List 的 JSON 檔不能有 BOM

用 Windows PowerShell 5.1 的 Set-Content -Encoding utf8 存 ingress-new.json，檔案開頭會多一個 BOM，oci 回報 must be in JSON format，更新沒有送出，原本的規則也沒被動到。改成用 .NET 寫成「UTF-8（不含 BOM）」就成功了。
