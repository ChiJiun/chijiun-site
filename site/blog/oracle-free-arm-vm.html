搶 Oracle Cloud 免費 ARM VM：從零到 SSH 登入的完整流程

2026-11-13 · 約 15 分鐘讀完
  • Oracle Cloud
  • OCI CLI
  • ARM
  • Always Free

Oracle Cloud 的 Always Free 有一台 ARM 主機（2 OCPU、12 GB 記憶體），但聽說東京 region 常常搶不到。我用 OCI CLI 和一支每分鐘重試的腳本去搶，第 24 次嘗試成功，前後約 42 分鐘。這篇把流程、指令、完整腳本，和我在 Windows 上踩到的坑一起記下來。

先講限制。搶得到有運氣成分，沒有人能保證多久。文中所有 OCID、IP、信箱、金鑰都用 <佔位符> 取代；免費額度以 Oracle 官方文件為準，我只讀過其中一頁，沒有逐項查證計費細節。

結果先看

  • 10:51腳本開始跑，第 1 次嘗試被判定為可重試錯誤，60 秒後再試
  • 11:10 左右第 12 次嘗試，仍然是可重試錯誤；期間我按了升級 Pay As You Go
  • 11:33第 24 次嘗試成功，一次就建出主機，沒有重複開機
項目內容
Region東京（ap-tokyo-1），只有一個 Availability Domain
ShapeVM.Standard.A1.Flex，2 OCPU / 12 GB
系統Ubuntu 24.04 aarch64，開機磁碟約 48 GB 可用
搶到的方式重試腳本，每輪約 1.5～2 分鐘（請求約 20 秒 + 查詢同名主機 + 等待 60 秒；24 次嘗試共花約 42 分鐘）

升級 Pay As You Go 後不久就搶到，但我沒有確認升級是否已經生效，所以不能說兩者有關。網路上有人說要先升級才搶得到，Oracle 並沒有這樣保證。

1. 先搞清楚「免費」到底包含什麼

我讀的是 Oracle 官方的 Always Free Resources 頁面，整理出和這篇有關的部分：

資源額度
A1 ARM 主機合計 2 OCPU / 12 GB，可以用在一台，或最多切成兩台
AMD 小主機VM.Standard.E2.1.Micro 最多 2 台，每台 1 GB 記憶體
磁碟開機磁碟與區塊磁碟合計 200 GB
出站流量每月 10 TB
位置主機與磁碟只能建在 home region
  • 升級 Pay As You Go 之後，Always Free 資源仍然免費，只有超出額度的部分才計費。
  • 7 天內 CPU 的第 95 百分位低於 20%，而且網路、記憶體（記憶體只看 A1）的使用率也低於 20%，主機可能被當成閒置回收。官方文字只明確寫 CPU 是第 95 百分位，網路與記憶體怎麼取樣，文件沒有細說。
  • Reserved Public IP 是否免費，文件沒有載明，所以我沒建。
  • 免費規格可選的映像檔只有 Linux，沒有 Windows。

我的帳號用 CLI 查到的 A1 配額上限遠大於免費額度（region 16 核 / 96 GB）。那是配額上限，不是免費額度，超過 2 OCPU / 12 GB 的部分可能計費，所以腳本預設就卡在 2 / 12。

2. 準備 OCI CLI 與 API 金鑰

2.1 建立 API 金鑰

  1. 登入 Console，右上角頭像 → My profile → API keys → Add API key。
  2. 選 Generate API key pair，下載私鑰，再按 Add。
  3. 畫面會顯示一段設定檔內容，裡面有 user、fingerprint、tenancy、region，先留著。
  4. 把私鑰放到 ~/.oci/oci_api_key.pem，並限縮權限（只有自己可讀寫）。

2.2 建立設定檔

把剛才的內容存成 ~/.oci/config，並把 key_file 改成私鑰的實際路徑：

[DEFAULT]
user=<USER_OCID>
fingerprint=<API_KEY_FINGERPRINT>
tenancy=<TENANCY_OCID>
region=ap-tokyo-1
key_file=<私鑰的完整路徑>

Always Free 只能開在 home region，所以 region 要填你註冊時選的那個。

2.3 安裝 OCI CLI（Windows 要注意路徑長度）

建議裝在獨立的 Python 虛擬環境裡，而且路徑要很短，原因在後面「踩坑」一節。我最後用的是：

py -3 -m venv C:\o
C:\o\Scripts\python.exe -m pip install oci-cli
C:\o\Scripts\oci.exe --version

驗證金鑰是否正確（唯讀指令）：

oci iam region-subscription list --tenancy-id <TENANCY_OCID> --output table

看到你的 home region 狀態是 READY，代表金鑰和 fingerprint 都正確。

2.4 查 A1 配額

oci limits value list --compartment-id <TENANCY_OCID> --service-name compute --all --query "data[?contains(name,'standard-a1')]"

我的帳號查到的上限遠大於免費額度（region 16 核 / 96 GB），但那是配額上限，不是免費額度，所以後面的腳本把規格固定在 2 OCPU / 12 GB。

3. 建網路

主機需要 VCN、Internet Gateway、路由和公開子網路。下面是 PowerShell 版本，全部建在 root compartment。官方的免費額度頁只列了 VCN 的數量上限，沒有明說這些網路資源收不收費，建議建完之後到 Billing 自己確認。

$T = "<TENANCY_OCID>"

$vcn = oci network vcn create --compartment-id $T --cidr-block 10.0.0.0/16 `
  --display-name a1-vcn --wait-for-state AVAILABLE --query "data.id" --raw-output

$igw = oci network internet-gateway create --compartment-id $T --vcn-id $vcn `
  --is-enabled true --display-name a1-igw --wait-for-state AVAILABLE `
  --query "data.id" --raw-output

# 預設路由表加一條 0.0.0.0/0 指向 Internet Gateway
$rt = oci network vcn get --vcn-id $vcn --query "data.\`"default-route-table-id\`"" --raw-output
'[{"destination":"0.0.0.0/0","destinationType":"CIDR_BLOCK","networkEntityId":"' + $igw + '"}]' |
  Set-Content -Encoding ascii routes.json
oci network route-table update --rt-id $rt --route-rules "file://C:/路徑/routes.json" --force

# 公開子網路
$sub = oci network subnet create --compartment-id $T --vcn-id $vcn --cidr-block 10.0.0.0/24 `
  --display-name a1-public --wait-for-state AVAILABLE --query "data.id" --raw-output

預設的安全清單（Security List）本來就放行 TCP 22，我用下面的指令確認，沒有改它：

$sl = oci network vcn get --vcn-id $vcn --query "data.\`"default-security-list-id\`"" --raw-output
oci network security-list get --security-list-id $sl --query "data.\`"ingress-security-rules\`""

預設是對 0.0.0.0/0 開放 SSH。搶到之後建議把來源限縮成自己的 IP，並考慮停用密碼登入。

4. 查腳本需要的三個值

# Ubuntu 24.04 ARM 映像檔
oci compute image list --compartment-id $T --operating-system "Canonical Ubuntu" `
  --operating-system-version "24.04" --shape VM.Standard.A1.Flex `
  --sort-by TIMECREATED --sort-order DESC --limit 1 --query "data[0].id" --raw-output

# Availability Domain 名稱
oci iam availability-domain list --compartment-id $T --query "data[].name"

子網路 OCID 就是上一節的 $sub。另外準備一把 SSH 金鑰，公鑰存成 ssh.pub，之後登入就用對應的私鑰。

5. 搶機腳本

邏輯很單純：呼叫「建立主機」API，失敗就看錯誤類型。沒容量、被限流、逾時這類錯誤等一下再試；LimitExceeded 或其他無法重試的錯誤就停止。

  • 設定 OCI_CLI_MAX_RETRIES=0，讓重試只由腳本控制，固定每 60 秒打一次。
  • 每次嘗試前先查有沒有同名主機，已存在就停止，避免重複開機。
  • 預設 2 OCPU / 12 GB、50 GB 開機磁碟。
#!/usr/bin/env bash
set -u
export OCI_CLI_MAX_RETRIES=0

WORKDIR="${WORKDIR:-$HOME/oci-grab}"
OCPUS="${OCPUS:-2}"        # 免費額度以 2 OCPU / 12 GB 為準
MEM="${MEM:-12}"
DELAY="${DELAY:-60}"       # 每次嘗試的間隔秒數
NAME="${NAME:-a1-free}"
BOOT_GB="${BOOT_GB:-50}"
SHAPE="VM.Standard.A1.Flex"

IMAGE="<IMAGE_OCID>"
SUBNET_ID="<SUBNET_OCID>"
ADS=("<AD_NAME>")      # 多個 AD 就列多個，會輪流試
COMPARTMENT="<TENANCY_OCID>"

mkdir -p "$WORKDIR"; cd "$WORKDIR" || exit 1
LOG="$WORKDIR/grab.log"; RESULT="$WORKDIR/result.txt"
[ -s "$WORKDIR/ssh.pub" ] || { echo "ssh.pub 不存在或是空的" | tee -a "$LOG"; exit 1; }
log() { echo "[$(date '+%F %T')] $*" | tee -a "$LOG"; }

i=0
while true; do
  # 同名主機已存在就停止，避免重複開機
  existing=$(oci compute instance list --compartment-id "$COMPARTMENT" --display-name "$NAME" \
    --query "data[?\"lifecycle-state\"!='TERMINATED'].id | [0]" --raw-output 2>/dev/null)
  if [ -n "$existing" ] && [ "$existing" != "null" ]; then
    log "已存在同名主機 $existing，停止"; echo "instance=$existing" > "$RESULT"; exit 0
  fi

  AD="${ADS[$((i % ${#ADS[@]}))]}"; i=$((i+1))
  log "第 $i 次嘗試，AD=$AD，${OCPUS} OCPU / ${MEM} GB"

  out=$(oci --no-retry compute instance launch \
    --compartment-id "$COMPARTMENT" --availability-domain "$AD" \
    --shape "$SHAPE" --shape-config "{\"ocpus\":$OCPUS,\"memoryInGBs\":$MEM}" \
    --image-id "$IMAGE" --subnet-id "$SUBNET_ID" --display-name "$NAME" \
    --boot-volume-size-in-gbs "$BOOT_GB" --assign-public-ip true \
    --ssh-authorized-keys-file "$WORKDIR/ssh.pub" \
    --wait-for-state RUNNING 2>&1)
  rc=$?

  if [ $rc -eq 0 ]; then
    inst=$(echo "$out" | grep -o '"id": "ocid1\.instance[^"]*"' | head -1 | cut -d'"' -f4)
    ip=$(oci compute instance list-vnics --instance-id "$inst" \
      --query 'data[0]."public-ip"' --raw-output 2>/dev/null)
    log "成功！instance=$inst public-ip=$ip"
    printf 'instance=%s\npublic_ip=%s\n' "$inst" "$ip" > "$RESULT"
    exit 0
  fi

  if echo "$out" | grep -qE 'Out of host capacity|Out of capacity|TooManyRequests|"status": 429|InternalError|"status": 500|timed out|ConnectionError|RequestException'; then
    log "可重試錯誤，${DELAY} 秒後再試"; sleep "$DELAY"
  elif echo "$out" | grep -q 'LimitExceeded'; then
    log "LimitExceeded：要求超過配額，請調低 OCPUS/MEM"; exit 2
  else
    log "不可重試的錯誤，停止。輸出：$out"; exit 3
  fi
done

我實際跑的版本，成功後用 python 解析主機 ID，結果解析失敗，result.txt 的 instance 和 public_ip 是空的。主機其實已經建好了，我是另外用 CLI 查到 IP。上面改成 grep 的寫法是事後修正，我沒有為了驗證這一行再搶一次主機。

6. 執行與監看

腳本要跑在不會睡眠的機器上。我是在 Windows 上用 Git Bash 執行，把 OCI CLI 的路徑加進 PATH：

export PATH="/c/o/Scripts:$PATH"
cd ~/oci-grab
chmod +x grab.sh
nohup setsid ./grab.sh > nohup.out 2>&1 &
tail -f grab.log

log 長這樣，沒搶到時會一直重複前兩行（log 只記錄腳本的判定，我沒有把 CLI 的原始錯誤訊息存下來，所以我無法逐次確認每次的原因）：

[2026-11-13 10:51:36] 第 1 次嘗試，AD=<AD_NAME>，2 OCPU / 12 GB
[2026-11-13 10:51:57] 可重試錯誤，60 秒後再試

要等結果出現，可以讓另一個程序輪詢 result.txt，一出現就通知自己。

補一個邊界情況：如果 --wait-for-state 等待逾時，錯誤訊息不一定包含 timed out，腳本會把它當成不可重試而結束（結束碼 3），但主機其實可能已經建好。重新執行腳本即可，它會先用同名檢查接住，不會重複開機。

7. 搶到之後

  1. 用 CLI 確認狀態是 RUNNING、規格是 2 / 12，並查出公開 IP。
  2. 用 SSH 登入。Ubuntu 的預設使用者是 ubuntu，Oracle Linux 是 opc： 
    ssh ubuntu@<PUBLIC_IP>
  3. 登入後檢查系統： 
    uname -m        # aarch64
free -h         # 約 11 GiB 可用
df -h /         # 約 48 GB

我沒有建 Reserved IP。臨時 IP 在正常重開機時不變，只有刪掉重建才會換。要不要建，建議先查 Oracle 定價頁再決定。

8. 順便開一台 AMD 小主機

AMD 小主機是獨立額度，我只試了一次就開成功（一次的結果，不代表一定容易）。但它是 x86、只有 1 GB 記憶體，跟 ARM 的差異如下：

A1 ARMAMD 小主機
CPU 架構ARM（aarch64）x86_64
CPU2 核1/8 OCPU，可短暫借用額外 CPU
記憶體12 GB1 GB（可用約 700 MB）
頻寬較高最高 50 Mbps（官方文件）
 
oci compute instance launch --compartment-id $T --availability-domain "<AD_NAME>" `
  --shape VM.Standard.E2.1.Micro --image-id "<X86_UBUNTU_IMAGE_OCID>" `
  --subnet-id "<SUBNET_OCID>" --display-name e2-free-1 --boot-volume-size-in-gbs 50 `
  --assign-public-ip true --ssh-authorized-keys-file ssh.pub --wait-for-state RUNNING

x86 映像檔要用 --shape VM.Standard.E2.1.Micro 去查，ARM 映像檔不能用在它上面。兩台加起來我用了 100 GB 磁碟，離 200 GB 上限還有空間。

9. 我實際開的資源，與官方文件寫的限制

  • 我實際開的：一台 A1（2 OCPU / 12 GB、50 GB 磁碟）加一台 AMD 小主機（50 GB 磁碟），磁碟合計 100 GB，沒有超過官方文件寫的 200 GB。
  • 官方文件寫的閒置回收規則：Always Free 主機若 7 天內 CPU 的第 95 百分位低於 20%，而且網路、記憶體（記憶體只看 A1）使用率也低於 20%，可能被回收。我才剛搶到，還沒有觀察到實際會不會被回收，所以這部分我沒有經驗可以分享。
  • 我沒有做的：Reserved IP（文件沒說免不免費）、負載平衡器、其他額外資源。

10. 我踩到的坑

10.1 Windows 路徑長度上限（最大的一個）

pip install oci-cli 失敗了兩次，錯誤是找不到檔案，並提示系統沒有啟用長路徑。原因是 oci-cli 內建了幾千個說明檔，有些檔名超長，放在 C:\Users\<你>\... 這種深路徑底下，完整路徑會超過 Windows 預設的 260 字元。

  • 虛擬環境放在 Temp 底下、或 C:\Users\<你>\ov，還是失敗。
  • 縮到 C:\o 才成功。
  • 另一個做法是啟用 Windows 長路徑，但那是系統設定，我選擇不動它。用 WSL 或 Linux 機器也能繞過這個問題。

10.2 虛擬環境建不起來

在很深的資料夾裡 python -m venv 會卡在 ensurepip，同樣是路徑長度造成的，換到短路徑就好。

10.3 PowerShell 的 JMESPath 跳脫

--query 裡的欄位名稱有連字號（例如 default-route-table-id）就必須加引號。PowerShell 要寫成 "data.\`"default-route-table-id\`""，bash 則是 'data."default-route-table-id"'。沒跳脫會看到 Unknown token '-'。

這個反斜線加反引號的寫法，我只在 Windows PowerShell 5.1 上實測過。PowerShell 7.3 之後改了傳給外部程式的引數處理方式，這寫法可能失效，到時請改用單引號版本；7.x 我沒有環境，沒測。

10.4 --route-rules file:// 的路徑

Windows 路徑要用正斜線：file://C:/路徑/routes.json，用反斜線會被當成多餘的參數。

10.5 睡眠與長時間執行

筆電睡眠或關機腳本就會停。重新啟動腳本沒有副作用，因為它每次嘗試前會先檢查同名主機。

10.6 腳本的結果檔 IP 是空的

前面第 5 節提過：我實際跑的版本用 python 解析主機 ID，解析失敗，result.txt 的 instance 與 public_ip 是空的。主機已經建好，我另外用 oci compute instance list 和 list-vnics 查到 IP。

我學到的

  • 這次我的 A1 是在第 24 次嘗試搶到，前面 23 次都被腳本判定為可重試錯誤，沒有出現會讓腳本停止的錯誤。我沒有存下原始錯誤訊息，所以不能保證每一次的原因都是沒容量。
  • 在 Windows 上裝 oci-cli，路徑要夠短，我最後是裝在 C:\o 才成功。
  • 升級 Pay As You Go 的時間點和搶到很接近，但我沒有確認升級是否生效，所以我不知道兩者有沒有關係。
  • 免費額度以 Oracle 官方文件為準，我只讀了其中一頁，計費細節沒有逐項查證。
