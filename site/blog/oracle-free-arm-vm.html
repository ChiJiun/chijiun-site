免費雲端主機：Oracle Always Free ARM VM 的額度、PAYG、費用與部署流程

2026-11-13 · 約 8 分鐘讀完
  • Oracle Cloud
  • Always Free
  • ARM
  • PAYG
  • 部署

Oracle Cloud 的 Always Free 提供一台長期免費的 ARM 雲端主機（2 核、12 GB 記憶體）。這篇整理它的免費額度、是否要升級 PAYG、其他雲端同規格的牌價，以及我申請主機並部署個人網站的流程。

簡介

雲端主機（VM）是租用的一台 24 小時開機、有公開 IP 的虛擬電腦；Always Free 在額度內不收費。A1 主機可能一時建不起來，需要重試：我在東京 region 用腳本試了 24 次、約 42 分鐘成功。文中的識別碼、IP 與金鑰都以 <佔位符> 代替。

  • Oracle Cloud Free Tier：註冊
  • Always Free Resources：免費額度明細
  • Free Tier 說明文件：試用、Always Free、升級
  • Oracle Cloud 價目表

免費額度

資源額度
A1 ARM 主機合計 2 OCPU / 12 GB，可用在一台，或最多切成兩台
AMD 小主機VM.Standard.E2.1.Micro 最多 2 台，每台 1 GB
磁碟開機磁碟與區塊磁碟合計 200 GB
出站流量每月 10 TB
位置只能建在 home region（註冊時選的 region）
  • 7 天內 CPU 第 95 百分位低於 20%，且網路、記憶體（只看 A1）也低於 20%，主機可能被當成閒置回收。
  • 映像檔只有 Linux。Reserved Public IP 是否免費，文件沒寫，我沒建。
  • 我的帳號查到的 A1 配額上限是 16 核 / 96 GB，那是上限，不是免費額度，規格要固定在 2 / 12。

PAYG（Pay As You Go）

  • Free Trial：$300 抵用額度、最多 30 天。註冊需要手機與信用卡，官方寫升級前不會扣款。
  • Always Free：不會到期，試用結束後已建好的資源不中斷。若 A1 超過 2 OCPU / 12 GB，會被停用，30 天後刪除，除非升級。
  • PAYG：付費帳號、無承諾期；Always Free 資源仍然免費，超出額度的部分才計費。

一定要升級嗎？官方文件沒有寫「要升級才能建立 Always Free 主機」，也沒有寫升級會提高成功率。我在重試期間升級了，但沒確認生效時間，無法判斷有沒有幫助。

怎麼升級：Console 頂端橫幅點 Upgrade；沒看到就點左上角 Oracle Cloud 標誌，在首頁右側欄找。

其他雲端的費用

2026-11-13 的公開牌價（不是我的帳單）：USD、每月 730 小時、含 50 GB 磁碟、不含稅與 IP 費。沒有任何一家剛好是 2 核 12 GB ARM，只能比最接近的規格。費用通常由運算（按小時）、磁碟（按 GB 月）、出站流量組成，有些另收公有 IP。

  • AWS 公有 IPv4 另計約 $3.65/月，未列入；Google Cloud 的 T2A 沒有東京，用新加坡；Hetzner 是歐元、不含 VAT，且我查到時顯示暫時無法購買，不能直接比較。
  • 出站流量：Oracle 每月 10 TB 免費；AWS、Azure 前 100 GB 免費，之後約每 GB $0.11～$0.12；Google Cloud 約每 GB $0.11～$0.12，我沒查到免費額度。

部署流程

順序：準備 OCI CLI → 建網路 → 查三個值 → 重複申請主機 → 登入確認 → 部署網站 → 切換網域。

步驟 1：準備 OCI CLI

Console → My profile → API keys → Add API key，下載私鑰到 ~/.oci/oci_api_key.pem，並把畫面顯示的設定存成 ~/.oci/config（region 要填 home region）：

[DEFAULT]
user=<USER_OCID>
fingerprint=<API_KEY_FINGERPRINT>
tenancy=<TENANCY_OCID>
region=ap-tokyo-1
key_file=<私鑰的完整路徑>

安裝 OCI CLI，Windows 要放在很短的路徑（原因見「踩到的坑」），再用唯讀指令驗證，home region 狀態應為 READY：

py -3 -m venv C:\o
C:\o\Scripts\python.exe -m pip install oci-cli
oci iam region-subscription list --tenancy-id <TENANCY_OCID> --output table

步驟 2：建網路

建 VCN、Internet Gateway、路由與公開子網路（PowerShell，建在 root compartment）：

$T = "<TENANCY_OCID>"
$vcn = oci network vcn create --compartment-id $T --cidr-block 10.0.0.0/16 `
  --display-name a1-vcn --wait-for-state AVAILABLE --query "data.id" --raw-output
$igw = oci network internet-gateway create --compartment-id $T --vcn-id $vcn `
  --is-enabled true --display-name a1-igw --wait-for-state AVAILABLE `
  --query "data.id" --raw-output

# 預設路由表加一條 0.0.0.0/0 指向 Internet Gateway
$rt = oci network vcn get --vcn-id $vcn --query "data.\`"default-route-table-id\`"" --raw-output
'[{"destination":"0.0.0.0/0","destinationType":"CIDR_BLOCK","networkEntityId":"' + $igw + '"}]' |
  Set-Content -Encoding ascii routes.json
oci network route-table update --rt-id $rt --route-rules "file://C:/路徑/routes.json" --force

$sub = oci network subnet create --compartment-id $T --vcn-id $vcn --cidr-block 10.0.0.0/24 `
  --display-name a1-public --wait-for-state AVAILABLE --query "data.id" --raw-output

預設的 Security List 已放行 TCP 22（來源 0.0.0.0/0），建議之後限縮成自己的 IP。

步驟 3：查三個值

# Ubuntu 24.04 ARM 映像檔
oci compute image list --compartment-id $T --operating-system "Canonical Ubuntu" `
  --operating-system-version "24.04" --shape VM.Standard.A1.Flex `
  --sort-by TIMECREATED --sort-order DESC --limit 1 --query "data[0].id" --raw-output

# Availability Domain 名稱
oci iam availability-domain list --compartment-id $T --query "data[].name"

第三個值是步驟 2 的子網路 OCID。另外準備一把 SSH 金鑰，公鑰在建立主機時交給 Oracle。

步驟 4：重複申請主機

oci compute instance launch \
  --compartment-id <TENANCY_OCID> \
  --availability-domain <AD_NAME> \
  --display-name a1-free \
  --shape VM.Standard.A1.Flex \
  --shape-config '{"ocpus":2,"memoryInGBs":12}' \
  --image-id <IMAGE_OCID> \
  --subnet-id <SUBNET_OCID> \
  --boot-volume-size-in-gbs 50 \
  --assign-public-ip true \
  --ssh-authorized-keys-file <SSH 公鑰檔> \
  --wait-for-state RUNNING

這是 bash 語法。我把它放進 bash 迴圈（Windows 用 Git Bash、放背景執行，電腦不能睡眠）：失敗後等 60 秒再送；送出前先用 --display-name 查有沒有同名主機，避免重複開機；每次嘗試寫進 log。

步驟 5：登入確認

用 oci compute instance list 確認狀態是 RUNNING 並查出公開 IP（我的腳本沒有把主機 ID 與 IP 寫進 log，見「踩到的坑」），再用 SSH 登入（Ubuntu 預設使用者是 ubuntu）：

ssh ubuntu@<PUBLIC_IP>
uname -m    # aarch64
free -h     # 約 11 GiB
df -h /     # 約 48 GB

步驟 6：部署網站

網站是純靜態檔案，我用 Caddy 提供。

6.1 開放 80 與 443

要放行兩層：Security List 與 Ubuntu 映像檔自己的 iptables。Security List 的 update 是整份取代，要先取出現有規則、加上新的、再整份送回：

$sl = "<SECURITY_LIST_OCID>"
oci network security-list get --security-list-id $sl --query "data.\`"ingress-security-rules\`"" > ingress-backup.json
# 把現有規則加上 80、443，存成 ingress-new.json（UTF-8，不要有 BOM）
oci network security-list update --security-list-id $sl `
  --ingress-security-rules "file://C:/路徑/ingress-new.json" --force
{"protocol":"6","source":"0.0.0.0/0","source-type":"CIDR_BLOCK","is-stateless":false,
 "tcp-options":{"destination-port-range":{"min":80,"max":80}}}

主機這層：預設 INPUT 規則的最後一條是拒絕，新規則要插在它前面（先用 sudo iptables -S INPUT 看順序），並存檔：

sudo iptables -I INPUT 5 -p tcp -m state --state NEW --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -p tcp -m state --state NEW --dport 443 -j ACCEPT
sudo netfilter-persistent save

6.2 安裝 Caddy 並放上網站

照 Caddy 官方安裝說明用 apt 套件庫安裝，然後 clone 網站：

sudo apt-get install -y debian-keyring debian-archive-keyring apt-transport-https curl gpg git
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/gpg.key | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt-get update && sudo apt-get install -y caddy

sudo mkdir -p /var/www/chijiun && sudo chown ubuntu:ubuntu /var/www/chijiun
git clone https://github.com/<帳號>/<repo>.git /var/www/chijiun

/etc/caddy/Caddyfile，先只聽 80，用 IP 測試（curl -I http://<VM_IP>/ 應回 200）：

:80 {
	root * /var/www/chijiun/site
	encode zstd gzip
	file_server
	handle_errors {
		rewrite * /404.html
		file_server
	}
}

讓網站在 push 之後自動更新：用 systemd timer 每 2 分鐘 git pull（兩個檔案放在 /etc/systemd/system/），再啟用：

# chijiun-sync.service
[Service]
Type=oneshot
User=ubuntu
WorkingDirectory=/var/www/chijiun
ExecStart=/usr/bin/git pull --ff-only --quiet

# chijiun-sync.timer
[Timer]
OnBootSec=1min
OnUnitActiveSec=2min
[Install]
WantedBy=timers.target
sudo systemctl daemon-reload
sudo systemctl enable --now chijiun-sync.timer
sudo systemctl reload caddy

6.3 切換網域（以 Cloudflare 為例）

  1. Cloudflare 的 SSL/TLS 是「完整（Full）」，它接受來源伺服器上不受信任的憑證，所以先讓 Caddy 用內建 CA 的憑證，Caddyfile 加一個網域區塊（site 是把上面 :80 區塊的設定抽成的 (site) 片段）： 
    chijiun.com, www.chijiun.com {
	tls internal
	import site
}
  2. 在原本提供網站的 Workers 專案移除自訂網域（從這一步到第 3 步完成之間網站是中斷的）。
  3. DNS 新增 A 記錄：名稱 @、內容為主機 IP、開啟橘雲（Proxy）。
  4. 把 www 的 CNAME 目標改成網域本身。

完成後網域根目錄與 www 都回 200。還沒做的：把 tls internal 換成 Let's Encrypt 憑證並改用 Full (strict)；Reserved IP（目前用臨時 IP，我沒測過重開機後會不會變，先不要停用或刪除這台主機）。

踩到的坑

  • Windows 路徑長度：pip install oci-cli 與 python -m venv（卡在 ensurepip）在深路徑下失敗，完整路徑超過 260 字元。放在 Temp 或 C:\Users\<你>\ov 都失敗，縮到 C:\o 才成功。
  • PowerShell 的 JMESPath 跳脫：--query 裡含連字號的欄位名要加引號，PowerShell 寫成 "data.\`"default-route-table-id\`""，否則出現 Unknown token '-'。我只在 Windows PowerShell 5.1 實測過。
  • file:// 路徑與 BOM：Windows 路徑要用正斜線（file://C:/路徑/x.json）；JSON 檔不能有 BOM，5.1 的 Set-Content -Encoding utf8 會加，結果是 must be in JSON format，要改用 UTF-8（不含 BOM）寫檔。
  • 腳本的 ID 與 IP 是空的：成功後我的腳本用 python 從回應解析主機 ID，解析失敗，log 與結果檔裡的 ID 與 IP 都是空的；主機已建好，用 oci compute instance list 與 list-vnics 查到 IP。
