Oracle 免費 ARM 主機：先升級 PAYG 才建得起來

2026-11-13 · 更新 2026-11-17

Oracle Cloud 的 Always Free 有一台不會到期的免費 ARM 主機（2 核、12 GB 記憶體）。用免費帳號去建，多半只會得到 Out of host capacity；把帳號升級成 Pay As You Go（PAYG）之後，通常馬上就建得起來，額度內仍然不收費。我自己也是綁卡升級之後，不到一小時就建起來了。

免費帳號為什麼建不起來

A1（VM.Standard.A1.Flex）是 Always Free 裡最搶手的規格。官方文件對 Out of host capacity 的解釋是：home region 暫時沒有 Always Free 規格的容量，可以換 Availability Domain、過一陣子再試，或升級成 PAYG。Always Free 的主機只能建在註冊時選的 home region，註冊後不能改，所以沒辦法靠換區域避開。

用腳本重試要等多久，沒有統計，只有個案。常被引用的重試腳本 hitrov/oci-arm-host-capacity 的討論裡（2023 到 2024 年的回報，專案已在 2024 年 8 月封存），有人等了 8 天、28 天、兩個半月，也有人跑了幾個月仍然沒成功。我的 home region 東京也有這類回報：NodeSeek 上有免費帳號搶了兩週、兩個月都沒搶到，也有人等了快一個月後決定升級。

升級 PAYG 之後

  • Hacker News 2026 年 8 月的討論：有人在 Ashburn 用新帳號一直遇到容量錯誤，升級 PAYG（等了一天）之後就不再遇到；也有人說不升級就一直沒有容量，升級後正常、用量仍在免費額度內。
  • hitrov/oci-arm-host-capacity：重試腳本的作者自己在說明裡建議升級 PAYG；討論裡有人升級後第一次就成功，也有人兩個帳號跑腳本兩天沒結果，送出升級幾小時後收到確認信，當下就建成。
  • 台灣開發者的紀錄（2026-05）：同樣是東京，免費帳號建 A1 被回報容量不足，升級約兩小時後通過，重新建立就成功。
  • LINUX DO（2026-10）：多則回覆說沒升級只能靠腳本搶，升級後馬上開得出來。

我的 home region 是東京，腳本失敗後等 60 秒再送。重試期間我綁了信用卡升級 PAYG，沒有另外等確認信，之後主機就建起來了：第 24 次，從開始重試算約 42 分鐘。

官方文件把升級列為處理方式之一，但沒有寫付費帳號有優先權，也沒有保證升級後一定有容量；Free Tier FAQ 只寫 PAYG 帳號適用的容量限制和 Always Free 帳號不同，沒有說明這個限制指的是什麼。「付費帳號優先」是社群的推論。

升級也不是保證，我找到三個反例：同一串 Hacker News 有人設好 PAYG 之後仍然拿不到免費的 ARM 主機，最後改成每月付費租用；LINUX DO 在 2026 年 11 月有人說已經升級但一直開不出來，沒有後續說明；GitHub 討論裡有人升級後腳本仍然回報沒有容量，但他從 Console 手動建得起來。

升級方式

  1. Console 頂端橫幅點 Upgrade；沒看到就點左上角 Oracle Cloud 標誌，在首頁右側欄找。官方說明另外列了選單路徑 Billing & Cost Management → Upgrade and Manage Payment，但註明適用對象是美國的新帳號，我沒走過。
  2. 信用卡會被暫時授權 100 美元，台灣的卡會收到一筆約新台幣三千多元的國外交易通知。Oracle 端會立即撤銷，實際退回的時間看發卡銀行。不接受虛擬卡、預付卡與一次性卡。
  3. 官方寫升級要一到兩天，社群回報從一兩個小時到一天都有，完成時會收到確認信，帳號的 Plan Type 變成 Pay As You Go。我綁完卡沒有另外等確認信，不到 42 分鐘主機就建起來了。
  • 升級後不能降回免費帳號。
  • 試用期內升級，300 美元的試用額度會保留到 30 天期滿或用完，之後才開始計費。
  • 升級可能失敗：有人換了幾家銀行的卡都在 100 美元授權被拒（GitHub），也有人回報多張卡升級失敗之後帳號被關閉（V2EX）。這些都是個案；社群的建議是用註冊時的同一張卡。

升級後不被收費

升級後 Always Free 的資源仍然免費，只收超出額度的部分。

資源免費額度
A1 ARM 主機合計 2 OCPU / 12 GB，可用在一台，或切成兩台
AMD 小主機VM.Standard.E2.1.Micro 最多 2 台，每台 1 GB
磁碟開機磁碟與區塊磁碟合計 200 GB，備份 5 份
出站流量每月 10 TB
  • A1 固定在 2 OCPU / 12 GB。2026 年 6 月 Oracle 把文件上的額度從 4 / 24 改成 2 / 12（InfoQ 的報導）。文件寫的是所有帳號每月 1,500 OCPU 小時、9,000 GB 小時，價目表卻仍寫付費帳號 3,000 / 18,000。社群的回報不一致：LINUX DO 到 2026 年 11 月仍有多人說 PAYG 跑 4 / 24 沒被收費（10 月、11 月），10 月那串也有一則說會扣費；NodeSeek 在 2026 年 7 月有人回報被扣款，發文者推測被扣的是 6 月改額度之後才升級的帳號（未經官方證實），現在才升級的人正屬於這一類；8 月 Hacker News 也有 PAYG 使用者跑 4 / 24，1 美元的警示響了。所以我固定在確定免費的 2 / 12。我的帳號查到的 A1 配額上限是 16 核 / 96 GB，那是上限，不是免費額度。
  • 其他會被收費的地方：磁碟合計超過 200 GB（刪掉主機後留下的磁碟也算）、建在 home region 以外的資源、選到付費的規格、多開主機。
  • Budget 只會寄信。官方稱它是軟性上限，本身不會停機（要自動處理得自己用 Events 串自動化），警示每 24 小時才評估一次，所以擋不住費用（官方說明）。社群的做法是設一個 1 美元的 Budget 當警示。
  • Compartment Quota 才是硬上限。它限制的是能建多少資源（官方說明）。把 A1 鎖在免費額度內的寫法如下。官方頁面沒有 A1 的範例，這是依其他規格的範例類推，我沒有實際套用過；這兩個 quota 以 Availability Domain 為範圍，每個 AD 各算一次，三個 AD 的 region 照這樣寫合計可以建到 6 OCPU / 36 GB，要鎖在 2 / 12 得用 where request.ad 只留一個 AD： 
    set compute-core quota standard-a1-core-count to 2 in tenancy
set compute-memory quota standard-a1-memory-count to 12 in tenancy
  • 閒置回收。官方條件是 7 天內 CPU 第 95 百分位、網路、記憶體（只看 A1）都低於 20%。現行文件沒有寫 PAYG 是否豁免；社群認為不會被回收，依據是 Oracle 2023 年寄給使用者的通知信（第三方轉述）與少數 PAYG 使用者的長期經驗。
  • 映像檔只有 Linux。Reserved Public IP 是否免費，文件沒寫，我沒建。

其他雲端的費用

2026-11-13 的公開牌價（不是我的帳單）：USD、每月 730 小時、含 50 GB 磁碟、不含稅與 IP 費。沒有任何一家剛好是 2 核 12 GB ARM，只能比最接近的規格。費用通常由運算（按小時）、磁碟（按 GB 月）、出站流量組成，有些另收公有 IP。

部署流程

順序：準備 OCI CLI → 建網路 → 查三個值 → 申請主機 → 登入確認 → 部署網站 → 切換網域。文中的識別碼、IP 與金鑰都以 <佔位符> 代替。

步驟 1：準備 OCI CLI

Console → My profile → API keys → Add API key，下載私鑰到 ~/.oci/oci_api_key.pem，並把畫面顯示的設定存成 ~/.oci/config（region 要填 home region）：

[DEFAULT]
user=<USER_OCID>
fingerprint=<API_KEY_FINGERPRINT>
tenancy=<TENANCY_OCID>
region=ap-tokyo-1
key_file=<私鑰的完整路徑>

安裝 OCI CLI，Windows 要放在很短的路徑（原因見「踩到的坑」），再用唯讀指令驗證，home region 狀態應為 READY：

py -3 -m venv C:\o
C:\o\Scripts\python.exe -m pip install oci-cli
oci iam region-subscription list --tenancy-id <TENANCY_OCID> --output table

步驟 2：建網路

建 VCN、Internet Gateway、路由與公開子網路（PowerShell，建在 root compartment）：

$T = "<TENANCY_OCID>"
$vcn = oci network vcn create --compartment-id $T --cidr-block 10.0.0.0/16 `
  --display-name a1-vcn --wait-for-state AVAILABLE --query "data.id" --raw-output
$igw = oci network internet-gateway create --compartment-id $T --vcn-id $vcn `
  --is-enabled true --display-name a1-igw --wait-for-state AVAILABLE `
  --query "data.id" --raw-output

# 預設路由表加一條 0.0.0.0/0 指向 Internet Gateway
$rt = oci network vcn get --vcn-id $vcn --query "data.\`"default-route-table-id\`"" --raw-output
'[{"destination":"0.0.0.0/0","destinationType":"CIDR_BLOCK","networkEntityId":"' + $igw + '"}]' |
  Set-Content -Encoding ascii routes.json
oci network route-table update --rt-id $rt --route-rules "file://C:/路徑/routes.json" --force

$sub = oci network subnet create --compartment-id $T --vcn-id $vcn --cidr-block 10.0.0.0/24 `
  --display-name a1-public --wait-for-state AVAILABLE --query "data.id" --raw-output

預設的 Security List 已放行 TCP 22（來源 0.0.0.0/0），建議之後限縮成自己的 IP。

步驟 3：查三個值

# Ubuntu 24.04 ARM 映像檔
oci compute image list --compartment-id $T --operating-system "Canonical Ubuntu" `
  --operating-system-version "24.04" --shape VM.Standard.A1.Flex `
  --sort-by TIMECREATED --sort-order DESC --limit 1 --query "data[0].id" --raw-output

# Availability Domain 名稱
oci iam availability-domain list --compartment-id $T --query "data[].name"

第三個值是步驟 2 的子網路 OCID。步驟 2、3 在同一個 PowerShell 視窗做（沿用 $T、$vcn）；步驟 4 起是 bash，變數不會帶過去，要換成實際的值。另外準備一把 SSH 金鑰，公鑰在建立主機時交給 Oracle。

步驟 4：申請主機

oci compute instance launch \
  --compartment-id <TENANCY_OCID> \
  --availability-domain <AD_NAME> \
  --display-name a1-free \
  --shape VM.Standard.A1.Flex \
  --shape-config '{"ocpus":2,"memoryInGBs":12}' \
  --image-id <IMAGE_OCID> \
  --subnet-id <SUBNET_OCID> \
  --boot-volume-size-in-gbs 50 \
  --assign-public-ip true \
  --ssh-authorized-keys-file <SSH 公鑰檔> \
  --wait-for-state RUNNING

帳號升級完成後，通常送一次就會成功。還沒升級，或升級後仍然遇到 Out of host capacity，才需要重試：我把它放進 bash 迴圈（Windows 用 Git Bash、放背景執行，電腦不能睡眠），失敗後等 60 秒再送；送出前先用 --display-name 查有沒有同名主機，避免重複開機；每次嘗試寫進 log。hitrov 腳本的作者建議至少隔 3 到 5 分鐘一次，他推測建立主機的 API 有呼叫次數限制（GitHub）；同一串也有人每 5 分鐘跑一次仍回報帳號被停用，原因不明。

步驟 5：登入確認

用 oci compute instance list 確認狀態是 RUNNING 並查出公開 IP（我的腳本沒有把主機 ID 與 IP 寫進 log，見「踩到的坑」），再用 SSH 登入（Ubuntu 預設使用者是 ubuntu）：

ssh ubuntu@<PUBLIC_IP>
uname -m    # aarch64
free -h     # 約 11 GiB
df -h /     # 約 48 GB

步驟 6：部署網站

網站是純靜態檔案，我用 Caddy 提供。

6.1 開放 80 與 443

要放行兩層：Security List 與 Ubuntu 映像檔自己的 iptables。Security List 的 update 是整份取代，要先取出現有規則、加上新的、再整份送回（在本機 PowerShell 做，沿用步驟 2 的 $vcn）：

$sl = oci network vcn get --vcn-id $vcn --query "data.\`"default-security-list-id\`"" --raw-output
oci network security-list get --security-list-id $sl --query "data.\`"ingress-security-rules\`"" > ingress-backup.json
# 打開 ingress-backup.json，把它的內容加上下面兩條 80、443 規則，另存成 ingress-new.json（UTF-8，不要有 BOM）
oci network security-list update --security-list-id $sl `
  --ingress-security-rules "file://C:/路徑/ingress-new.json" --force
{"protocol":"6","source":"0.0.0.0/0","source-type":"CIDR_BLOCK","is-stateless":false,
 "tcp-options":{"destination-port-range":{"min":80,"max":80}}}

主機這層：預設 INPUT 規則的最後一條是拒絕，新規則要插在它前面（先用 sudo iptables -S INPUT 看順序；下面的行號 5、6 是我的輸出，請依你的調整），並存檔：

sudo iptables -I INPUT 5 -p tcp -m state --state NEW --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -p tcp -m state --state NEW --dport 443 -j ACCEPT
sudo netfilter-persistent save

6.2 安裝 Caddy 並放上網站

照 Caddy 官方安裝說明用 apt 套件庫安裝，然後 clone 網站：

sudo apt-get install -y debian-keyring debian-archive-keyring apt-transport-https curl gpg git
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/gpg.key | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt-get update && sudo apt-get install -y caddy

sudo mkdir -p /var/www/chijiun && sudo chown ubuntu:ubuntu /var/www/chijiun
git clone https://github.com/<帳號>/<repo>.git /var/www/chijiun

這個 repo 必須是公開的：clone 和之後的 git pull 都沒有帶認證。

/etc/caddy/Caddyfile，先只聽 80，用 IP 測試（curl -I http://<VM_IP>/ 應回 200）：

(site) {
	root * /var/www/chijiun/site
	encode zstd gzip
	file_server
	handle_errors {
		rewrite * /404.html
		file_server
	}
}

:80 {
	import site
}

讓網站在 push 之後自動更新：用 systemd timer 每 2 分鐘 git pull（兩個檔案放在 /etc/systemd/system/），再啟用：

# chijiun-sync.service
[Service]
Type=oneshot
User=ubuntu
WorkingDirectory=/var/www/chijiun
ExecStart=/usr/bin/git pull --ff-only --quiet

# chijiun-sync.timer
[Timer]
OnBootSec=1min
OnUnitActiveSec=2min
[Install]
WantedBy=timers.target
sudo systemctl daemon-reload
sudo systemctl enable --now chijiun-sync.timer
sudo systemctl reload caddy

6.3 切換網域（以 Cloudflare 為例）

  1. Cloudflare 的 SSL/TLS 是「完整（Full）」，它接受來源伺服器上不受信任的憑證，所以先讓 Caddy 用內建 CA 的憑證，Caddyfile 加一個網域區塊（site 就是 6.2 定義的片段），改完執行 sudo systemctl reload caddy： 
    chijiun.com, www.chijiun.com {
	tls internal
	import site
}
  2. 在原本提供網站的 Workers 專案移除自訂網域（從這一步到第 3 步完成之間網站是中斷的）。
  3. DNS 新增 A 記錄：名稱 @、內容為主機 IP、開啟橘雲（Proxy）。
  4. 把 www 的 CNAME 目標改成網域本身。

完成後網域根目錄與 www 都回 200。還沒做的：把 tls internal 換成 Let's Encrypt 憑證並改用 Full (strict)；Reserved IP（目前用臨時 IP，我沒測過重開機後會不會變，先不要停用或刪除這台主機）。

踩到的坑

  • Windows 路徑長度：pip install oci-cli 與 python -m venv（卡在 ensurepip）在深路徑下失敗，完整路徑超過 260 字元。放在 Temp 或 C:\Users\<你>\ov 都失敗，縮到 C:\o 才成功。
  • PowerShell 的 JMESPath 跳脫：--query 裡含連字號的欄位名要加引號，PowerShell 寫成 "data.\`"default-route-table-id\`""，否則出現 Unknown token '-'。我只在 Windows PowerShell 5.1 實測過。
  • file:// 路徑與 BOM：Windows 路徑要用正斜線（file://C:/路徑/x.json）；JSON 檔不能有 BOM，5.1 的 Set-Content -Encoding utf8 會加，結果是 must be in JSON format，要改用 UTF-8（不含 BOM）寫檔。
  • 腳本的 ID 與 IP 是空的：成功後我的腳本用 python 從回應解析主機 ID，解析失敗，log 與結果檔裡的 ID 與 IP 都是空的；主機已建好，用 oci compute instance list 與 list-vnics 查到 IP。
